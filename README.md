# MongoDB_CRUD_web_app
This is a school project. It is a web application made with the dash framework and the Pymongo driver. 

When creating software I always add comments describing what the code does. This increases the codes maintainability. When I go back to old code I wrote I can quickly understand what the program does because I put it in simple terms in comments. In this project I created a method that took a dictionary and passed it as a query in a read method. This created a more adaptable program. Instead of hardcoding methods to make specific queries, I could just pass a query to the method. 

The approach I take to solving a problem usually follows the same pattern. I determine what needs to be done. This could be a requirement, feature, or code that does something. Once I know what must be done I start breaking down the problem into smaller and smaller pieces. I then solve the smaller sub problem of the larger problem and repeat this process until the whole problem is solved. This method works very well because I can focus on a small part of a problem instead of the entire problem at once.
